k-ID integration handoff

For Maya + Khushi · @k-id/core web SDK · test key

The plan in one line

k-ID's age gate wraps the whole app; our own screens fill its waiting, too-young and said-no states; every feature that changes by age sits inside a KidPermission check.

See every screen in the clickable prototype. The setup below uses the values Michelle chose: Ollie as the icon, k-ID's default privacy and terms links (fine in test mode), and support@example.com as a placeholder support address.

1. Install and wrap the app

npm install ./k-id-core-web.tgz
import {
  KidCoreProvider, KidSessionProvider, KidAgeGate,
  KidAgeGatePass, KidAgeGatePending, KidAgeGateFail,
  KidAgeGateProhibited, KidAgeGateError,
} from '@k-id/core'

const declare = {
  permissions: [
    { name: 'camera-access' },             // snap a photo to prove a find
    { name: 'ai-media-upload' },           // the photo goes to the AI check
    { name: 'photo-video-sharing' },       // share finds with friends (Lena's parent-OK moment)
    { name: 'send-accept-friend-requests' },
    { name: 'in-game-purchases' },         // FastSpring: Ollie outfits, adult walk pass
    { name: 'ai-voice-mode' },             // Inworld: talk to Ollie
    { name: 'ai-companion-chatbot' },      // Inworld: Ollie as an AI companion
    { name: 'voice-chat' },                // voice notes to friends, moderated by Modulate
    { name: 'multiplayer' },               // group outings with other players
    { name: 'text-chat-private' },         // group chat (filtered for kids)
    { name: 'real-time-location-sharing' },// share where you are with the group (always off for kids)
  ],
  iconUrl: 'https://explore-your-block.vercel.app/assets/ollie-icon.png',
  supportEmail: 'support@example.com',
}

// our brand, so k-ID's screens match the app
const appearance = {
  variables: {
    colorPrimary: '#1F2030', colorOnPrimary: '#FFFFFF',
    colorText: '#1F2030', colorTextMuted: '#6B6A75',
    colorSurface: '#FFFFFF', colorSurfaceMuted: '#F6F3EE',
    colorBorder: '#EFE9E0', colorDanger: '#E5484D',
    fontFamily: "'Nunito', system-ui, sans-serif", radius: '20px',
  },
}

export function Root() {
  return (
    <KidCoreProvider publishableKey={KID_PUBLISHABLE_KEY}
      baseUrl="https://kai-api.test.k-id.com/fapi/v1"
      declare={declare} appearance={appearance}>
      <KidSessionProvider jurisdiction="auto"
        sessionId={load('kid.sessionId')} challengeId={load('kid.challengeId')}
        onSession={(id) => save('kid.sessionId', id)}
        onChallenge={(id) => save('kid.challengeId', id)}
        onClaim={(token) => fetch('/api/kid/claim', { method: 'POST', body: JSON.stringify({ token }) })}>
        <KidAgeGate>
          <KidAgeGatePending><WaitingForGrownUp /></KidAgeGatePending>
          <KidAgeGateProhibited><TooYoungHere /></KidAgeGateProhibited>
          <KidAgeGateFail><GrownUpSaidNo /></KidAgeGateFail>
          <KidAgeGateError><CouldNotReachKid /></KidAgeGateError>
          <KidAgeGatePass><App /></KidAgeGatePass>
        </KidAgeGate>
      </KidSessionProvider>
    </KidCoreProvider>
  )
}

The publishable key and base URL are in k-ID's instructions. The publishable key is safe in the browser. The secret key stays on the server: /api/kid/claim uses it to claim the result from the claimToken.

3. Gate each feature

Show a feature only when k-ID turns it on, and use managedBy to pick the right fallback.

// kids without camera get Ollie's quiz instead
<KidPermission name="camera-access" fallback={<KidQuizProof />}>
  <CameraProof />
</KidPermission>

// sharing: GUARDIAN → our "needs a parent's OK" screen, PROHIBITED → hide the button
const { can, get } = useKidPermission()
const share = get('photo-video-sharing')
if (can('photo-video-sharing')) showShare()
else if (share?.managedBy === 'GUARDIAN') showAskParent()   // Lena, 14, Germany
// PROHIBITED: render nothing

Group mode: the strictest rules win

When people go out together, show only spots that suit everyone, and turn a feature on only if k-ID allows it for every member.

// each member has their own k-ID session (claimed on the backend)
const groupCan = (name) => members.every(m => m.permissions[name] === true)
const youngest = members.reduce((a, b) => (a.age < b.age ? a : b))
const spots = SPOTS.filter(s => members.every(m => s.ages.includes(m.band)))
// banner: "Following {youngest.name}'s rules: location sharing off · chat filtered"
showLocationSharing = groupCan('real-time-location-sharing')
showGroupChat      = groupCan('text-chat-private')

Purchases stay with each person: the adult buys the Family Outing Pack on their own phone through FastSpring, and it unlocks for the group. Kids never see a buy button.

4. Our own age dial (optional)

The prototype's swipe dial can replace k-ID's age input: collect the age ourselves and pass it as age={{ age }} on KidSessionProvider (Tier 3 in the README). Check requirements.approvedAgeCollectionMethods first. If a country only allows date of birth, fall back to k-ID's KidCollectAge.

For the UI look, we pick kid, teen or adult from the age (under 13, 13 to 17, 18 and over). Permissions always come from k-ID, never from the age band.

5. Settings on the Me tab

<KidSettingsProvider sessionId={load('kid.sessionId')} onChallenge={(id) => save('kid.settingsChallengeId', id)}>
  <KidSettings />
</KidSettingsProvider>

Player-managed permissions get a toggle. Guardian-managed ones ask a grown-up in one email. Prohibited ones are hidden.
